# Content-owned compact beatmap selection

## Why
Native source-qualified immutable map storage exists, but the application cannot
select, save, copy or restore a map for a content instance. A full envelope does
not fit the bounded project/arrangement images. Selection must integrate the
existing Config, content, assignment and history owners before collection.

## What Changes
Add compact content intent independent of scalar analysis, exact legacy-compatible
Copy/Pair/Bank and Portable metadata, atomic Config selection, original-job Loader
adoption and model-free fresh source restore. Extend existing asset/history owners
and exact retirement proof retention through actual last-reader cleanup.

## Non-goals
No inference/backend adoption, B4 editor, live variable trajectory, new scheduler,
job pool, current-map registry or full B3/P6/Human acceptance is introduced. No
heavy file/hash/map parsing or cleanup belongs on realtime or the UI thread.
