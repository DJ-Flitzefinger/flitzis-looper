# Version-five common support

Retain the existing priority of a strict 20–80% middle, selected whole-source fit
or selected maximal IOI run. Only when those provide no eligible common region
may the new fallback inspect the published regions.

Require two or three unique exact source-duration thirds, exact selected-region
membership, at least one strictly extending witness, and every published region
within `abs(region.bpm / selected.bpm - 1) <= 0.00025`. Any duplicate, non-third
or conflicting region refuses the entire fallback; do not filter witnesses.

Construct one min/max hull over all those bounds and run the existing strict
24-observation/30-second fit over every original event in that interval. Preserve
original ordinals, the five median/MAD iterations, exclusion/count/coverage limits
and the residual gate. A failed hull has no smaller-window retry. Never join
independently rephased islands or replace the selected BPM with the hull's free fit.

The two existing adaptive probe windows evaluate the exact selected fractional
period and nearest integer with the same common mask, pivot and quality limits.
The common object need not be an existing region, but all its support derives from
the canonical published witnesses. Keep the published region count at most five
and include the common metadata in the existing retained-JSON byte accounting.

Python validates new hull provenance only for version five. It reconstructs the
complete qualifying canonical-third set and preferred-middle availability from
raw observations, then recomputes every supporting third and the hull's
candidate-neutral robust mask and free fit. An omitted qualifying third or an
omitted eligible preferred middle cannot manufacture fallback eligibility.
Versions one through four retain their existing readers and validators. Execution
receipts remain valid for versions four and five. No valid v4 estimate is
reanalyzed merely because its optional counterprobe was inconclusive.
