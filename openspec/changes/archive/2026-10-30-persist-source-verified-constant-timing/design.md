# Historical evidence and fresh runtime ownership

The versioned envelope retains complete supported raw native QM evidence,
configuration/input transform, full source/mono timebase, independent counts,
timing-error provenance, accepted identity, exact period and signed origin, and
independent acceptance policy. Native reconstruction recomputes the canonical
accepted identity; Python validates the envelope shape without becoming a second
evidence authority. Unsupported extensions are discarded per analysis record.

Historical evidence job identity is preserved. It is distinct from the new
runtime source generation/request/epoch captured synchronously at restore
admission. The same TimingAdoptionGuard adopts only after actual complete PCM and
source-byte verification. One bounded worker performs heavy reconstruction; all
later publication and callback checks use the fresh native owner. Pending,
failed, rejected and stale work establishes no current accepted timing.

Production project flush asks the native current owner for a verified export,
never a saved envelope or historical ticket. Automatic without acknowledgement
stays unavailable, with no legacy BPM promotion. Loader restoration keeps this
authority through verification, then refreshes restored intent only when the
native current resolver confirms actual adoption. Manual/Tap overrides remain
explicit and old projects migrate to Legacy or Manual, never accepted Automatic.

Original hashing remains observed loader association, with a current source-file
rehash at persistence boundaries. Immutable copy-first decoder input and ABA proof
remain C1. This change neither launches the app nor establishes listening/device
or musical/default acceptance.
