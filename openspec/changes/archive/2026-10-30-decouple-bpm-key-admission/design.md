# Component admission and publication

All existing pre-read and execution gates use the same mandatory BPM geometry.
Optional key work includes retained source, wire and conversion/FFT/CQT/widening
workspace before allocation. Failure or overflow of the optional component does
not change the512MiB primary limit or crop the source. Model subprocess accounting
retains its existing separate scope.

LoadedAnalysis carries key_status ready/skipped_budget/not_requested/failed and
optional key_error. Both current event routes keep the required display key string;
unknown without work is distinct from an actual completed unknown classification.
These are control DTO facts, not timing/phase/source authority or new persisted
compatibility state. Existing scientific analysis remains available as before.

KeyMetadataAnalysis admission captures request and analysis epoch without changing
correction. Matching ready completion may publish a source version and remove only
the captured old correction; newer correction remains authoritative. All other
outcomes settle without key/shift mutation. Optional key capacity failures remain
visible while independent BPM proceeds. Both fresh-load completion routes and
same-source reanalysis use these rules; skipped reanalysis merges old detected key
into valid new BPM metadata. Cancellation/replacement/stale owners remain unchanged.

No callback I/O, locks, allocation-heavy work, Python/GIL or inference is added.
Reuse source-bound workers and immutable publication/OwnACK/retirement. Verify
targeted behavior and two actual long sources once each, persisting raw observations
for later estimator replay rather than duplicating neural runs.
