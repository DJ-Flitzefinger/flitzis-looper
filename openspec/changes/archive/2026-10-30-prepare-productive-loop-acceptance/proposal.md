# Prepare productive G3c device and listening evidence

G3c2's hardware-free musical-period correction is complete. Actual device output
and sustained human listening remain open. Normal loading and Analyze do not
establish current accepted timing, and a separate engine cannot observe the GUI
engine. A reviewable human-run measurement packet must therefore expose a genuine
productive preparation route and retain evidence suitable for later comparison.

## Scope

- Add explicitly invoked preparation/observation tooling using the application's
  existing accepted publication, current ownership and derived acknowledgement.
- Preserve source/configuration, full accepted revision, physical/musical loop,
  rate, output clock, Key Lock, stem/DSP and device/capture identities.
- Supply bounded offline feature comparison and a human 30-minute listening
  record, with concrete private artifact workflow and hardware-free tests.

## Non-goals and realtime boundary

No automatic playback, capture, analyzer default adoption, inferred human labels,
device acceptance, variable-map SYNC, cache/residency or B5 delay compensation.
The user starts and operates the app and recorder. Evidence scans, JSON, hashes,
logging and file writes stay outside the realtime callback. Observation is not a
second timing owner. Synthetic fixtures never pass actual device/listening gates.
