## Request and selection

The persisted option is disabled by default, with dormant bounds50 and170 BPM.
Bounds are finite, within30..300, strictly ordered and inclusive. Validate the
complete option before Native configuration and persistence. Snapshot it before
queuing cold/incoming loads and explicit full/tempo-only analysis. Later setting
changes affect later admissions; restore and Copy do not reinterpret saved BPM.

Disabled and already in-range successful primary results preserve their exact
existing scalar/method and do no additional QM work. Only an original successful
NN v4/v5 primary outside the range may request unchanged own-QM preparation and
scalar validation. Retain its precise value only when it is inside the range and
the actual published periods satisfy:

`abs(slow - 2*fast) * (span/slow) <= 0.005`

Here pN=60/NN_BPM, pQ=60/QM_BPM, slow=max(pN,pQ), fast=min(pN,pQ), and span is the
minimum of the complete NN and actual complete QM analyzer extents. Preserve this
operation order. Do not substitute rounded classes, free periods, phase alignment
or endpoint cropping. This is a bounded primary/QM half/double selection policy,
not exhaustive range search. Stored v5 alternative summaries are not independently
admitted values. Missing/conflicting/limited NN results are not rescued by range.

## Failure and ownership

An enabled request must not newly publish an outside-range scalar. Prepare and
admit a valid rejected result before optional QM work. QM, budget, allocation,
panic and late serialization failures return that rejected result; if even its
metadata cannot be owned safely, return BPM0/methodNone and a bounded explanation.
Keep independent key outcomes and raw grid positions. Latched cancellation or
supersession remains whole-request failure before fallback and publication.

Reuse existing complete-source ownership, own-QM preparation and512MiB accounting.
Retire QM intermediates before final serialization. The original v6 same-period
corroboration path remains unchanged. Its outside result is filtered, not treated
as a successful independent NN value. Unconfigured scientific automatic analysis
also filters outside values, without inventing NN provenance or running QM again.

Existing positive analysis may remain on an unavailable reanalysis completion,
under current independent-component rules. The new request's diagnostic must
explain its failure without claiming the retained old value matched the range.
Manual/Tap, newer source/timing edits, OwnACK, loops, BPM Lock, key correction,
raw origin and master/transport retain their existing authority.

## Saved evidence

Changed/rejected accepted neural results use schema7, backend beat_this_bpm_range,
policy neural-user-range-v7. The bpm_range block stores inclusive bounds, the
original schema/backend/policy/status/BPM header, outcome and optional selection.
Top-level raw NN arrays, math and execution remain unchanged once; a base v6 keeps
its unchanged corroboration. Validate a shallow original v4/v5/v6 view. A selected
QM result has the existing strict source/preparation and own numeric evidence,
replayed full-extent half/double drift, and exact scalar/status equality.
Rejected results use BPMnull/statusinsufficient and no selection block. Older
versions reject the new field evennull. Copy/restore validate data without DSP,
runtime lookup, migration or automatic upgrade.

Settings explain future-request scope. Current automatic guidance identifies range
selection and QM CPU work while preserving the actual NN device receipt; busy or
manual/Tap state must not present cached support as current inference.
