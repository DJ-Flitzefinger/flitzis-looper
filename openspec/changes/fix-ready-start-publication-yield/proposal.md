## Why

An ordinary GUI PAD start can join a genuine already accepted Native resident
window. The controller nevertheless returns after obtaining that ticket and
waits for another UI/runtime poll before publishing the original attack. This
adds an avoidable control delay after readiness is already established.

## What Changes

- Inspect the returned original window ticket during the same controller call.
- Publish the same captured attack immediately when its exact ticket is accepted.
- Keep genuinely pending tickets, exact independent edit dependencies,
  cancellation, Native publication guards and the total eight-attempt bound.

## Non-goals

This bounded control fix does not change original T, execution E, source content,
quantization, scheduling, DSP, start modes or the late-start product contract. It
does not establish a fixed latency reduction, resolve all missing-onset causes,
or certify device/listening acceptance. No audio callback work, Python/GIL access,
allocation or blocking is added; all changed code remains on the control thread.
