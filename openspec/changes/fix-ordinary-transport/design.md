## Target and order

One Native callback-written record keeps ContentKey/lifetime, ordinary semantic
source epoch, effective frame and original global scheduler sequence. Successful
explicit start, pitch retrigger and true playable resume promote it. Group starts,
Hold release and no-effect/refused operations do not. STOP/runtime/pitch revisions
do not erase valid source history; unload/replacement invalidate, placement moves
follow content. Valid temporarily unavailable targets refuse rather than fall
back to editor selection.

## Atomic effects

OFF START uses the existing single-PAD residency/captured-start path with an
opaque expected-target guard. Right STOP snapshots target or absence internally,
fences old pending launches and stops only the qualified target. Non-audible peers
receive request-only launch cancellation, preserving pause/Hold intent. Recording
and STOP ALL keep their existing global ownership.

ON-to-OFF reserves queue, revisions and retirement before publishing its complete
runtime image, source-bound peer stops and old-launch fences. One control barrier
keeps later starts behind that effect. A current playable target keeps its voice
position/generation; no target means no survivor. Refusal mutates nothing; accepted
callback pressure remains pending, not a rollback. Existing batch tickets retain
ownership until terminal observation.

## Lock and delivery

Python model/UI/MIDI resolve requested Lock independently of MultiLoop. One
qualified application/source/master survives mode and selection changes; hierarchy
requalification does not bootstrap a different anchor. Native same-reference
service is reused. API3 preflight only reflects types/signatures; it performs no
audio/device work. Focused interaction tests and one headless3-PAD transition
replace repeated broad suites, performance stress or analysis inference.
